# 20 — Testing Strategy

**Shape:** many fast unit tests, a solid integration layer, few but high-value end-to-end tests, plus human exploratory testing that automation cannot replace.

## 1. Levels

| Level | Tool | Scope | Runs |
|---|---|---|---|
| **Unit** | pytest | Domain logic, policies, price and coupon computation, state machines | Every commit |
| **Component** | Vitest + Testing Library | UI components, all states, a11y assertions | Every commit |
| **Integration** | pytest + real Postgres/Redis | Repositories, migrations up/down, transactions, concurrency | Every commit |
| **API / contract** | Schemathesis on generated OpenAPI | Fuzzing, schema conformance, **auth on every route** | Every commit |
| **Database** | pytest | Constraints, cascades, indexes, partial uniques, migration reversibility | Every commit |
| **End-to-end** | Playwright | Signup→enrol→learn→certify · discovery→brochure · checkout→payment→entitlement | Every PR |
| **Failure-path** | pytest | Dependency down, timeout, malformed input, forged signature | Every commit |
| **Security** | pytest + Semgrep + ZAP | AuthZ matrix, injection, rate limits, webhook forgery, IDOR | Every commit + S13 |
| **Cross-platform** | Manual + CI | Both machines, identical results | S1 D7, then each milestone |
| **Performance** | k6 + Lighthouse CI | Catalog and checkout under load; Core Web Vitals | S13, S20 |
| **Load** | k6 | Sustained and spike load against staging | S13 |
| **Deployment validation** | Smoke suite | Post-deploy in every environment | Every deploy |
| **Production smoke** | Playwright subset | Critical flows against PROD | Every production deploy |
| **Exploratory** | **Humans** | Use the product like a hostile user | Every sprint, Day 13 |

## 2. Coverage gates

| Module | Gate |
|---|---|
| `commerce`, `payments`, `entitlement`, `credential`, `security` | **85%** |
| Everything else | 70% |

**Coverage is a floor, not a goal.** An untested authorization branch fails review regardless of the percentage.

## 3. Critical flows that must be automated before production

Registration and verification · login + MFA · **authorization matrix per role** · free enrolment · paid checkout end to end · **duplicate and forged webhooks** · coupon limits under concurrency · subscription renewal and failure · **refund → entitlement revocation → credential revocation** · certificate issuance, verification and revocation · brochure generation and access control · file upload authorization · progress tracking and completion.

## 4. Test data

Factories, never fixtures with hard-coded ids. Each test independent — no ordering dependencies, no shared mutable state. Database-per-test isolation using transactions rolled back after each test. **Mock only at the system boundary** (payment provider, email, meetings, LLM) — never mock your own database, because then you are testing your mock.

Seed data for local development is generated by `make seed` and is realistic enough to catch layout and performance problems that three rows never will.

## 5. What human testing catches that automation does not

| Human activity | Catches |
|---|---|
| Exploratory testing | Unexpected flows, confusing copy, dead ends |
| Cross-browser | Rendering and behaviour differences |
| Mobile on a real device | Touch targets, keyboard overlap, scroll traps |
| Screen reader | Announcement order, missing labels |
| **Adversarial testing** | Authorization gaps, IDOR, tampering |
| Performance perception | "It feels slow" that no metric shows |
| **Failure injection** | Alerts that were never wired correctly |

**Two hours per sprint are allocated to exploratory testing on Day 13.** It is not optional and it is not review.

## 6. Things that look done but are not

| Looks done | Actually needs |
|---|---|
| "Payment works" | Duplicate webhook · forged signature · cancelled payment · lost webhook + reconciliation · refund → entitlement revoked |
| "Coupon works" | Expired · over global limit · over per-user limit · below minimum · wrong product · **two concurrent redemptions of the last use** |
| "Login works" | Wrong password · unverified email · locked account · expired session · revoked session · MFA required · brute-force lockout |
| "Upload works" | Wrong type · oversized · malicious content · filename traversal · another user's file |
| "Certificate works" | Verification page · revocation · duplicate issuance under retry · signature validity |
| "Monitoring works" | **An alert actually fired when something broke** |
| "It works locally" | It works in CI, with real Postgres, from a clean clone, on the other person's machine |

## 7. CI test execution

```
Commit → lint + typecheck (30 s)
       → unit tests (60 s)
       → integration with Postgres + Redis service containers (2–3 min)
       → contract tests against generated OpenAPI (60 s)
       → build (2 min)
       → security scans (2 min)
       → E2E smoke (3 min)
Total target: under 10 minutes
```

Slower than ten minutes and people stop waiting for it, which defeats the purpose.
